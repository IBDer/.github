# Security and Safety Reporting / 安全问题报告

Please do not open a public issue for vulnerabilities, exposed credentials, identifiable patient information, or content that could create an immediate medical-safety risk.

如果问题涉及漏洞、泄露的凭证、可识别的患者信息，或可能造成即时医疗安全风险，请不要创建公开 Issue。

Use **Security → Report a vulnerability** in the affected repository to submit a private report. If private vulnerability reporting is not available for that repository, do not post sensitive details publicly; open a minimal issue asking a maintainer to establish a private contact channel. Include only the minimum information needed to reproduce or assess the problem, and do not include real patient data.

请通过受影响仓库中的 **Security → Report a vulnerability** 提交私密报告。如果该仓库尚未启用私密漏洞报告，请不要公开敏感细节；可以创建一个不包含细节的 Issue，请维护者建立私密联系渠道。只提供复现或评估问题所需的最少信息，并且不要提交真实患者数据。

## What to include / 报告内容

- A concise description of the issue
- The affected repository, page, or version
- Reproduction steps using synthetic or redacted data
- Potential privacy, security, or medical-safety impact
- Any known mitigation

- 问题的简要描述
- 受影响的仓库、页面或版本
- 使用合成数据或脱敏数据的复现步骤
- 潜在的隐私、安全或医疗风险
- 已知的缓解方法

We will acknowledge reports when they are received, assess severity, limit further exposure, and publish an appropriate correction or advisory after affected users and maintainers can act safely.

收到报告后，我们会确认问题、评估严重程度、限制进一步暴露，并在相关用户和维护者能够安全采取行动后发布适当的更正或公告。
